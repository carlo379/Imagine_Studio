# Series Bible and Episode Books

Open a Story / Series project and choose **Develop → Series & episodes**.

The workspace has three destinations: **Series Bible**, **Episodes**, and **Series Library**. The Bible defines the recognizable world. Each episode has a separate storybook, title, script, scenes, and selected references.

## Build the shared world

Open the Series Bible and work through Series identity, Characters, Locations, Key props, Look & rules, and Continuity. Start with the details you know. Blank entries are optional. Genre, tone, role, lighting, audience, and style offer common choices plus custom entries.

Set **Visual style** on the first **Series identity** spread, directly after the premise and before developing the cast. **Cinematic stylized 3D animation** is available as a preset, alongside other styles and custom entry. This saved series style guides new reference images and is included in each episode's foundation. Existing images are retained; changing the style does not automatically regenerate them.

Define SampleHero in Characters, then select **Develop appearance**. The visual studio opens over the book: write his details and voice direction, upload a reference or generate a character sheet directly with front, back, side, three-quarter, and head views, then approve it as the reusable identity. Additional outfit sheets preserve the approved character. Generate an image only when you choose a generation action. Return to the Bible with the approved reference saved.

Saving a renamed character, location or prop updates its linked visual-workshop and sheet labels by stable card ID. The same rule applies to an episode's own book cards. Matching names in other cards or projects are unaffected. An associated library reference adopts the new title only when it still uses the old entity name; its mention handle stays unchanged. Independent workshop names and outfit/view titles are preserved. Saved prompts, media, previous versions and existing episode foundation snapshots are retained. Opening development also repairs sheet labels left stale by earlier versions.

Saving a card also refreshes the copied descriptions on every linked sheet, including approved sheets and outfit views. Appearance edits merge into the workshop profile wherever its values still match the previous source card; deliberate workshop refinements retain precedence. Sheet descriptions follow that effective workshop profile. Resaving an unchanged card or opening development repairs stale copies from earlier versions. Saved image jobs, prompts and output filenames remain unchanged.

**Appearance & distinguishing details** is available in the visual studio as the same saved profile field from the book, separately from **Character summary**. Initial reference sheets and additional outfits include those appearance details. Up to 1,000 characters are used in image direction; longer descriptions remain fully saved and the panel displays that limit. **Edit image direction** shows the generated direction and allows a deliberate custom override.

Characters, locations and props offer **Inspiration images** with up to five inputs, selected together or added over time. Add architecture, room views or key object references, preview/remove each thumbnail, and generate a location candidate using all selected inputs in order. Uploading inputs does not approve or replace the location. **Add approved location to inspiration** explicitly includes the existing identity in the five-input allowance. **Choose a finished location image** remains a separate adoption action for a complete image you want to reuse directly. Additional coverage angles continue to use the approved location as their identity.

Locations and props follow the same pattern. A main location supports scouting and reference angles. A charging station, vehicle, or favorite tool supports a primary reference and object views. Existing Asset Studio identities can be linked from Series Library.

## Develop characters, locations and props

Each visual-development window follows **Describe → Add inspiration → Prepare prompt → Generate → Choose**. Describe uses the large left pane with tabs. Locations have Architecture & layout, Light & atmosphere, and Story context. Characters have Appearance, Outfit & details, and Story & voice; props have Design & materials and Story context. Edits remain in place while switching tabs. Save details and Continue to Add inspiration appear below the editor.

**Inspiration images** are inputs you supply to guide AI. **Add images** offers **From computer**, **From Library**, and **Paste image**. The Library browser is displayed in the left column when you enter Add inspiration; search by image name, select uploaded or approved generated images, then add them to the tray. It reuses the saved images without uploading copies. Add up to five together or over time, preview/remove each thumbnail, or explicitly add the currently approved image as inspiration. Adding inspiration never approves it. The current style, selected model, input count and number of outputs appear beside the main **Generate** button. **Advanced direction** edits that button's instructions; custom direction replaces the automatic wording, so include your desired style and defining details. Reset returns to the current saved recommendation. **Additional instruction (Optional)** adds extra AI guidance in Advanced direction. The development flow is **Describe → Add inspiration → Prepare prompt → Generate → Choose**. **Prepare image prompt with AI** starts preparation in step 03 using the selected image connection. Status, AI notes and the editable prompt stay in that workspace. **Use prompt & continue** saves the reviewed prompt and opens step 04; click Generate separately to create images, then review them in step 05. Switching between Image 2 and Grok preserves the exact reviewed prompt and its approval; Generate uses the selected connection. It does not request another AI writing pass or offer model-specific prompt optimization. Changing the additional instruction requires a new preparation and review.

Generated **candidates** appear in the image workspace. Select a thumbnail to review it large, then choose **Approve as character**, **Approve as location**, or **Approve as prop**. Approval selects the image for future work. A badge and border identify the approved image. Replacing it asks for confirmation; existing episode snapshots stay intact.

Already have a finished image? Open **Use a finished image** and choose the file. Review its preview and explicitly approve it. This action is separate from inspiration uploads.

The approved image's **⋯ → Clear approval** removes the selection without deleting the image. It stays available as a candidate, while saved episodes, shots and request snapshots retain existing images. Optional outfits and alternate views wait until a main image is approved again. Clearing selection does not remove shared Asset Studio references used by older work.

Use **Reject** for an unsuitable candidate, optionally choosing a reason and adding notes. It moves into the collapsed **Rejected** section and stops appearing in reusable image pickers. **Return to review** makes it a candidate again without approving it. Rejection notes remain review information; they do not automatically regenerate or revise an image.

Open a candidate's **⋯** menu for **Move to Trash** or **Download image**. Trash is recoverable with Undo/Restore. Restoring a previously rejected image preserves its rejection until Return to review. Images used by saved references, episodes or requests are protected; the dialog lists those uses without removing anything.

After approval, **Save & return to Bible/episode** saves the work and returns to the same book. Optional outfits, location angles and prop views stay collapsed beneath it. **Open in Image Studio** remains available for deeper editing. Visual style changes affect new image directions; saved images and pinned episode foundations remain intact.

## Write individual adventures

Choose Episodes and open a storybook, or create a new one. Rename it in **Episode title**. The episode begins with access to the Bible's foundation; choose recurring cast, places, and props, then add new entries for this adventure.

The first episode save captures its series foundation. Changing the Bible later preserves this episode's script and references. **Consult Series Bible → Refresh from current Bible** explicitly updates that foundation without rewriting saved media.

Write the premise, story beats, and script, or upload TXT, Markdown, Fountain, or DOCX. Imports are organized locally and reviewed before populating the book. Filled fields stay unless replacement is selected. Undo restores the pre-import book.

**Develop script with AI** uses the selected existing ChatGPT or Grok writing connection. Review and directly edit scenes and shot directions. A targeted revision can change one scene. Connected scripts require a new version for edits, preserving the prior storyboard. No automatic provider fallback is used.

Save a manual script into the episode and create its storyboard, or create a storyboard from the reviewed AI script. Existing episode scripts require explicit replacement confirmation. Script scenes and references pass into the selected episode; other episodes remain intact.

## Reuse and produce

Approved Bible references appear in Series Library and can be selected in future episodes. New episode references remain local until **Save to Series Bible** is selected. Approving a new reference leaves earlier shots intact. **Update storyboard references** explicitly updates unfinished shots in the current episode; selected video takes remain preserved.

The normal production tools remain available: Script, Storyboard/Image Studio, Video Studio, and Edit. **Bible & episode** opens a reference panel while keeping the current tool in place. **Open in Image Studio** edits the same reference draft and provides a return action to the book.

Both books retain the physical cover, opening and page-turn animations, equal pages, internal scrolling, phone page layout, and reduced-motion fade. Autosave and saving before navigation preserve paused typing, including spaces. Conflicting saves retain a recovery draft instead of silently overwriting another version.

Use **Read manuscript** for a readable live preview and Markdown or JSON download. **Download illustrated PDF** exports saved details, confirmed references, and the episode script without an AI request.

## Earlier work

Existing stories, episodes, scripts, shots, media, and earlier World Builder records are retained. The Bible exposes **Review earlier storybook** and a deliberate copy into empty shared fields. Earlier episode-specific material is not automatically classified as series canon. Existing saved episode scripts are available in the Script chapter.

Script uploads default to **Import script**: review the text and import it unchanged, preserving saved Bible and Storybook details. AI does not run on file selection. After reviewing the upload, **Compare with saved details using AI** optionally starts a duplicate/conflict review with the selected connection; apply its changes only after choosing what to keep.
